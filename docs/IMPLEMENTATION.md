# Первый работающий прототип

**Обновление 0.6.0:** реализованы закрытые OHLCV/объёмы, offline и независимое forward-сравнение, watchdog, фоновое получение данных/начислений и цепочка решения → риск → исполнение. Текущая спецификация, команды, результаты и оставшиеся границы — [VALIDATION.md](VALIDATION.md). Описания 0.4/0.5 ниже относятся к предыдущим срезам. Модель остаётся qwen3.5:4b, текущие контекст/промпт — market-summary-v3 / qwen-trader-v3.


Версия 0.5.0, 14.10.2026. CLI и панель на Python 3.11+, без зависимостей. Локальная Qwen 3.5 4B через установленную Ollama предлагает намерения для рыночных виртуальных сессий. Есть симулятор и исполнитель Alpaca Paper; реальные средства не используются. MCP — необязательный компонент.

## Панель управления

Дополнение от 14.10.2026: аналитика наблюдений и короткая память Qwen реализованы в analytics.py. История до 600 наблюдений за последний час, расчёт окон 1/5/15 минут, изменения с прошлого запроса и восемь последних значимых событий сохраняются в SQLite; старые сессии совместимы. Панель показывает готовность данных конкретного запроса. Это история bid/ask, без объёмов и внешних свечей. Подробности — [MODELS.md](MODELS.md). Уже работающий сервер нужно перезапустить для загрузки обновления.

«Подключить Qwen» запускает в фоне проверку локальной qwen3.5:4b; до успеха запуск алгоритма Qwen заблокирован. Выбрать источник рынка и «Qwen 3.5 4B · главный ИИ», затем бюджет/риск/длительность. Модель анализирует подготовленный снимок после пяти наблюдений. Блок «Решение главного ИИ» показывает действие, причину, задержку и время данных; AI_REQUEST/AI_DECISION доступны в журнале/отчёте. Стопы, пауза и дедлайн не ждут ответа модели. Инструкция — [MODELS.md](MODELS.md).

Вверху — подключение **Alpaca Paper Only**: Key ID / Secret Key, баланс, BTC/USD, позиции и последние 50 заявок. Ключи только в памяти сервера. После подключения источник «Alpaca · виртуальные ордера» исполняет Paper-сессию с заданным бюджетом, риском и дедлайном. «Проверка исполнения · один вход и выход» делает один цикл без ИИ. Демо/локальный рынок используют отдельный симулятор. Настройка, требования к выделенному счёту и статус внешней проверки — [ALPACA.md](ALPACA.md).

Файл запуска проверяет совместимую панель на портах 8787/8788 и открывает её. Если ни одной нет, запускает сервер на свободном порту. При оставшемся старом сервере обновлённая версия использует 8788.

Двойной клик по `launch-dashboard.cmd` в корне проекта — браузер откроется автоматически. Если панель уже запущена на стандартном порту, используется существующий сервер. Адрес `http://127.0.0.1:8787`. Альтернативный запуск:

```powershell
python -m traid_ai dashboard
```

Панель читает ту же базу `data/paper.sqlite3`, что и CLI. Другую базу/порт можно указать флагами `--db` и `--port`. Не запускать второй исполнитель CLI для этой базы одновременно с выполняемой сессией панели: OS-блокировка отвергнет его.

Слева — настройки и история сессий. Справа — состояние, средства, PnL, комиссия, просадка, время, цена с отметками виртуальных сделок, кривая портфеля и открытая позиция. На узком экране ссылки «Настройки и запуск» / «Наблюдение» быстро переводят к нужному разделу. Графики показывают значения при наведении; обновление раз в секунду.

- **Запустить:** параметры фиксируются; demo ускорено, paper использует реальное время. Демо BTC/USD — искусственные цены, это явно подписано.
- **Пауза входов:** запрещает новые покупки, сохраняя выходы, stop и дедлайн. **Разрешить входы** снимает паузу. Состояние сохраняется в базе.
- **Завершить:** на следующем шаге запрашивается/формируется свежая котировка и закрывается виртуальная позиция. При недоступности данных — UNRESOLVED. Публичный запрос может занимать до восьми секунд.
- **Восстановить:** запускает выбранную незавершённую сессию с прежними параметрами и дедлайном. После рестарта сервера выполнение не возобновляется самовольно.
- **Скачать отчёт:** JSON с параметрами, состоянием и полным журналом. На экране отображаются последние 50 записей из 500 последних событий, история выбора — до 100 сессий; база сохраняет весь журнал.

Новая сессия не начинается при наличии незавершённой в этой базе. Сначала выбрать и восстановить прежнюю, затем завершить. Закрытие вкладки не влияет на исполнение; закрытие сервера/сон компьютера прекращает доступность. При Ctrl+C сервер пытается завершить сессию, сохранённые остатки доступны для восстановления.

Панель привязана к `127.0.0.1`, проверяет Host, Origin и локальный управляющий токен. Публичное развёртывание и доступ по сети не поддерживаются. В графиках стоимость портфеля вычисляется из тех же наблюдений и fills, что и итоговый отчёт, включая комиссии.

## Что реализовано

- `demo`: искусственные bid/ask и ускоренный прогон модельной сессии.
- `paper`: публичные BTC/USD из GET `/0/public/Ticker?pair=XBTUSD` Kraken, с виртуальными сделками в реальном времени.
- Проверка bid/ask, конечных чисел, источника, порядка и возраста наблюдений.
- Механическая тестовая стратегия `demo-momentum-v1`: после пяти наблюдений запрашивает вход выше среднего +0.3%, выход ниже среднего −0.3%. Она нужна для проверки цепочки, её доходность не исследована.
- Отдельный расчёт количества по риску и экспозиции, округление вниз, моделируемые комиссии и adverse slippage.
- Одна спотовая виртуальная позиция, стоп, максимум удержания, лимит потерь и просадки.
- Прекращение входов и закрытие в буфере перед дедлайном без модуля решений. При отсутствии свежей котировки открытая позиция остаётся UNRESOLVED.
- SQLite сохраняет параметры, наблюдения, решения, риск-вердикты, fills и состояние. В одном шаге всё фиксируется атомарно. Повтор того же step_id не создаёт fill заново.
- OS-блокировка допускает один CLI-исполнитель на файл базы. После падения процесса блокировка снимается ОС; сохранённую сессию можно возобновить.
- Отчёт содержит cash, количество, PnL, комиссии, моделируемое проскальзывание, просадку и время последней оценки.

## Быстрый запуск

Открыть PowerShell в корне проекта:

```powershell
python -m traid_ai demo
```

Демо заканчивается автоматически за несколько секунд. Оно выводит `SESSION_ID`, события и JSON-отчёт. Продолжительность модельного времени по умолчанию 60 минут; реальное ожидание отсутствует. Демо не является историческим бэктестом.

Сессия на текущих котировках на четыре часа:

```powershell
python -m traid_ai paper --capital 1000 --risk-percent 0.5 --exposure-percent 25 --loss-limit-percent 3 --duration-minutes 240
```

Бюджет 1000 — виртуальные USD. `paper` ждёт реальное время и может ничего не купить. Интервал запросов по умолчанию 10 секунд, меньше 10 не допускается. Закрытие консоли прекращает процесс; для восстановления использовать resume. Сон компьютера нарушает доступность.

## Отчёт и восстановление

Вставить напечатанный SESSION_ID вместо `YOUR_SESSION_ID`:

```powershell
python -m traid_ai report YOUR_SESSION_ID
python -m traid_ai report YOUR_SESSION_ID --events
python -m traid_ai resume YOUR_SESSION_ID
```

По умолчанию база `data/paper.sqlite3`. Для отдельного эксперимента:

```powershell
python -m traid_ai demo --db data/experiment.sqlite3
python -m traid_ai report YOUR_SESSION_ID --db data/experiment.sqlite3
```

При resume конфигурация и исходный дедлайн восстанавливаются из базы; параметры риска не меняются. Закрытая сессия выводит отчёт, торговля не начинается заново. На публичном источнике после дедлайна сначала запрашивается новая котировка для выхода; при неудаче остаётся UNRESOLVED. Повторить resume после восстановления источника.

Ctrl+C запрещает входы и завершает процесс. Если позиции нет, статус CLOSED; если есть — UNRESOLVED, без выдуманного fill по старой цене. Для закрытия виртуальной позиции нужна команда resume со свежими котировками.

Коды выхода: 0 — завершение без неразрешённого остатка, 1 — ошибка запуска/хранилища, 2 — UNRESOLVED. Все машинные времена в журнале — UTC.

## Настройки по умолчанию

| Параметр | Значение | Значение для модели |
| --- | --- | --- |
| `--capital` | 1000 | Виртуальные USD |
| `--risk-percent` | 0.5 | Расчётная потеря до стопа с ожидаемыми расходами, % начального бюджета |
| `--exposure-percent` | 25 | Максимум стоимости входа с комиссией относительно equity |
| `--loss-limit-percent` | 3 | Потеря от начального бюджета, включая mark-to-market |
| `--fee-percent` | 0.1 | Виртуальная комиссия каждой стороны |
| `--slippage-bps` | 5 | Ухудшение ask при покупке и bid при продаже |
| `--duration-minutes` | demo 60 / paper 240 | Длительность сессии, больше 1 и до 1440 |

Внутренние ограничения v0.2: стоп 2%, просадка 5%, удержание до 3600 секунд, буфер завершения 60 секунд, возраст котировки до 30 секунд, шаг количества 1e−8, минимум входа 5 USD. Это параметры модели, а не актуальные правила биржи или рекомендация по риску. Выход продаёт весь виртуальный остаток без биржевого минимума.

## Ограничения и следующие работы

Qwen получает лишь короткие признаки по последним котировкам. Это не исторические свечи, новости или полный рынок; доходность не оценена. Локальный симулятор исполняет объём немедленно по bid/ask с заданным ухудшением, без глубины/очереди. Alpaca учитывает ответы ордеров, частичные fills, фильтры актива и сверку. Stop между опросами может исполниться хуже ожидаемого.

У ticker нет используемой здесь временной метки биржевого события: `observed_at` — время получения HTTP-ответа. Проверка возраста контролирует локальные наблюдения, но не доказывает свежесть биржевого стакана. Пропуск более 30 секунд сбрасывает окно стратегии. Ошибка сети не приводит к подмене данных синтетическими ценами.

Нереализованный PnL оценивается по последнему bid и не включает будущую комиссию/проскальзывание выхода. Slippage уже отражён в цене fills, отдельно вычитать его из PnL нельзя. Комиссии также уже включены. LLM и платных данных нет; расходы на них не вычисляются.

Событийный Paper-адаптер сохраняет подготовку/отправку, состояния ордеров и отдельные сверки баланса. Риск повторно проверяет лимитную цену после округления; дедлайн и свежесть котировки проверяются перед POST. UNKNOWN не повторяется вслепую. Поздние комиссии Alpaca пока не сверяются по activities; отчёт отмечает оценку комиссии и предварительный PnL. Независимый watchdog отсутствует. Демо не доказывает рыночного преимущества.

Следующий срез: расширить признаки и историю, затем измерить качество решений Qwen после расходов. Установка модели и корректный JSON не подтверждают прибыльности. Freqtrade не устанавливался.

## Проверка

14.10.2026 пройдены все 66 тестов.

```powershell
python -m unittest discover -s tests -v
```

Проверки охватывают риск, округления, дедлайн, восстановление, отказы, блокировки, CLI/HTTP, Paper-ордера и Qwen. Для модели проверяются схема, отсутствие ключей/tools, изменённый портфель, устаревший/не сохранённый снимок, пауза, смена digest, ошибка/медленный ответ и передача намерений Paper-исполнителю. Настоящая Qwen отдельно проверена на текущих котировках: ответы WAIT приняты и записаны с задержкой около 2 секунд. Внешнее Paper-исполнение подтверждено отдельно — ALPACA.md.

Формат публичного ticker проверен по [официальной документации Kraken](https://docs.kraken.com/api-reference/market-data/get-ticker-information) 13.10.2026. Публичный источник не означает возможность открыть торговый аккаунт; возрастные и региональные условия будущего live остаются отдельным ограничением.
