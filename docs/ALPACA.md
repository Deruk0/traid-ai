## Через нашу панель

14.10.2026 пользователь сообщил о создании аккаунта. Предоставленные client_id/client_secret совпали с публичными примерными значениями на странице Issue tokens; это не подтверждение наличия личных Paper-ключей. Их не использовали и не сохраняли. По [Authentication](https://docs.alpaca.markets/us/docs/authentication) client_credentials предназначен для Broker API и пока не поддерживается Trading API. Для этой панели нужны Key ID / Secret Key из личного Paper Trading в app.alpaca.markets; вход в документацию ReadMe не создаёт торговый Paper-счёт.

1. Открыть launch-dashboard.cmd и раздел Alpaca Paper Only вверху страницы.
2. Если использование Paper Only разрешено правилами сервиса для пользователя, получить Key ID и Secret Key именно виртуального счёта в [Alpaca Dashboard](https://app.alpaca.markets/).
3. Ввести ключи в поля панели и нажать «Подключить Paper». В чат ключи не отправлять.
4. Проверка GET /v2/account на Paper endpoint включает наблюдение: баланс, позиции, последние 50 заявок и BTC/USD.

Ключи остаются в памяти локального Python-процесса; поля очищаются после отправки. Ключи не сохраняются в SQLite, на диске, в отчётах и HTTP-логах. После отключения или рестарта требуется повторный ввод. Альтернатива — ALPACA_API_KEY и ALPACA_SECRET_KEY в окружении сервера; панель предлагает отдельную кнопку, когда обе переменные присутствуют.

Фоновый опрос каждые 15 секунд, HTTP timeout 10 секунд на попытку. GET при сетевой ошибке повторяется один раз; POST не повторяется. Сбой ресурса показан рядом с последними данными; для баланса, позиций и заявок есть время успешного получения. Котировка содержит биржевое время; возраст более 30 секунд отмечается как устаревший. Работающий исполнитель дополнительно сверяет состояние; сетевые задержки могут увеличить интервал.

Клиент использует фиксированные HTTPS-хосты paper-api.alpaca.markets и data.alpaca.markets. Для выбранной Paper-сессии разрешены POST /v2/orders и DELETE /v2/orders/{id}; live endpoint отсутствует. Пользовательский URL не принимается, редиректы запрещены. Ошибки показывают код и ограниченное сообщение Alpaca с удалёнными ключами. Доступ к endpoint не подтверждает допустимость аккаунта по возрасту и региону.

Локальные demo/paper и внешний Paper-счёт — разные портфели. Для исполнения выбрать источник «Alpaca · виртуальные ордера», бюджет, риск и длительность. Алгоритм «Проверка исполнения · один вход и выход» проверяет механику и завершается после одного цикла; обычный алгоритм — тестовое правило движения цены. Оба не используют ИИ и не имеют доказанной доходности.

Требуется отдельный пустой Paper-счёт без других ботов, ручных позиций и открытых заявок. Бюджет ограничивается свободными USD и non_marginable_buying_power, без плеча. Единственный исполнитель держит OS-блокировку аккаунта и базы. На стороне Alpaca Paper деньги виртуальные.

Вход — BTC/USD, limit IOC; цена, количество и резерв комиссий проверяются Risk Engine с правилами актива. Выход — market GTC по подтверждённому остатку. client_order_id и SUBMITTING сохраняются до POST. Filled_qty и средняя цена учитываются накопительно без повторного начисления fills; реальный остаток и деньги берутся из сверенных ответов позиции/счёта. Оценка комиссии показана отдельно и повторно из баланса не вычитается.

Проверка 14.10.2026 вернула 40310000 «cost basis must be >= minimal amount of order 10». Для новых Paper-сессий установлен нижний порог входа 10 USD после округления и резерва расходов; лимиты пользователя не повышаются автоматически. Если допустимый размер ниже минимума — вход не отправляется. Этот наблюдаемый порог дополняет min_order_size из assets; при изменении требований брокера нужен пересмотр адаптера.

Таймаут POST оставляет UNKNOWN. Повторная отправка той же покупки запрещена; исполнитель ищет заявку по client_order_id и сверяет позиции, баланс, открытые заявки и историю. При отсутствии ID не менее 60 секунд и трёх успешных полных проверках с интервалом не менее 10 секунд сохраняет ORDER_ABSENT_CONFIRMED и переходит к завершению. Это подтверждение отсутствия по наблюдаемому состоянию API, не полученный от брокера отказ; история сохраняет исходное неизвестное намерение. При противоречии, ошибке сети или найденной заявке подтверждение отсутствия не выполняется.

Пауза запрещает входы и отменяет незавершённую покупку, затем сверяет гонку отмены с исполнением. Выходы и дедлайн сохраняются. Завершение и восстановление работают через панель; CLI resume для Alpaca запрещён. CLOSED требует нулевой позиции, отсутствия pending и успешной сверки. При остатке, недоступности брокера или посторонней активности — UNRESOLVED. Восстановление UNKNOWN завершает прежнюю сессию, не возобновляет покупки.

Отключение/смена ключей заблокированы во время работы Paper-исполнителя. После остановки с UNKNOWN сначала подключить тот же счёт и восстановить сессию. Закрытие вкладки не останавливает сервер; завершение процесса оставляет журнал для восстановления. Отключение наблюдения само по себе не закрывает позиции Alpaca.

## Официальный MCP

Установлен alpaca-mcp-server 2.4.0 из [официального проекта](https://github.com/alpacahq/alpaca-mcp-server) в отдельном data/alpaca-mcp-env. Основной dashboard не зависит от пакета. Повторная установка на новом компьютере:

    python -m venv data/alpaca-mcp-env
    .\data\alpaca-mcp-env\Scripts\python.exe -m pip install -r requirements-alpaca-mcp.txt

.codex/config.toml содержит регистрацию alpaca_paper, enabled = false. Ключи панели не передаются в MCP; он необязателен для нашего исполнителя. Абсолютные пути соответствуют этому компьютеру; при переносе обновить command, args и cwd.

Такой же отключённый сервер зарегистрирован в пользовательском config.toml Codex; остальные настройки сохранены. CLI codex mcp get alpaca_paper --json подтверждает регистрацию и allowlist. На текущем проекте без Git-root CLI не подхватил проектную конфигурацию, поэтому оставлена и пользовательская запись. При включении обновить enabled в применяемых конфигурациях.

После подтверждения допустимости Paper Only и получения ключей:

- Передать ALPACA_API_KEY и ALPACA_SECRET_KEY через окружение процесса Codex, без хранения в отслеживаемых файлах и без вывода в чат.
- Поставить enabled = true в проектной конфигурации и перезапустить клиент/открыть новую сессию для загрузки MCP.
- Проверить чтение текущей котировки BTC/USD. Ввод ключей в веб-панель подключает только dashboard, не MCP в Codex.

Launcher scripts/start_alpaca_mcp.py принудительно задаёт ALPACA_PAPER_TRADE=true, ALPACA_TOOLSETS=crypto-data и официальный DATA_API_URL независимо от исходного окружения. Транспорт stdio, HTTP-порт не открывается. В конфигурации Codex разрешены восемь инструментов криптоданных. Пакет дополнительно регистрирует документацию и некоторые исторические stock-data; наша allowlist их скрывает. Отправка, изменение и отмена ордеров не доступны.

Набор account официального MCP содержит update_account_config, а trading объединяет чтение с размещением/отменой заявок. Эти наборы не включены как якобы «только чтение». Наблюдение за балансом и заявками выполняет наша панель.

## Дальнейшая торговля и ограничения

BrokerEngine реализует этот первый Paper-адаптер поверх Engine. Дальнейшие ограничения: независимый watchdog отсутствует; поздние FEE/CFEE и корректировки Alpaca ещё не сверяются по activities; PnL отчёта предварительный. Неожиданная корректировка баланса останавливает автоматические действия. Нельзя обещать закрытие при недоступности сервиса или размере остатка меньше минимума.

Пользователю нет 18. [Paper Trading](https://docs.alpaca.markets/us/docs/paper-trading) описывает Paper Only и виртуальную криптоторговлю, но не устанавливает явно допустимость аккаунта для несовершеннолетнего. Это остаётся неподтверждённым условием; до регистрации уточнить у сервиса. Вымышленный возраст, чужие аккаунты и обход ограничений не предусмотрены.

Paper не воспроизводит полностью задержки, очередь исполнения или влияние сделки на рынок. Прибыль в песочнице не доказывает прибыльность в live.
