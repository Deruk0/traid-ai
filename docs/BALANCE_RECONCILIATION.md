# Максимум удержания и зависшая сверка — 18 октября 2026 года

## Решение пользователя

Пользователь выбрал: для новых сессий отключить MAX_HOLD по умолчанию и оставить необязательную настройку. Config.max_hold_seconds теперь может быть None. Пустое поле «Максимум удержания позиции» в панели означает отсутствие отдельного выхода по времени удержания; конечное значение в минутах переводится в положительное целое число секунд. CLI demo/paper принимает `--max-hold-minutes`. Общий дедлайн сессии, скользящий стоп, лимиты потери и остальные независимые защиты действуют по-прежнему.

Существующие сессии не переписываются. Явные старые значения сохраняются; Config.from_dict без max_hold_seconds восстанавливает исторические 3600 секунд. Новая конфигурация сериализует отключение как null. В современных снимках v7 значение включено в policy и position_management, участвует в хеше; replay проверяет его, если поле присутствует. Исторические снимки без этого поля остаются допустимыми по прежним правилам. Изменение срока в конфигурации нового снимка делает replay несовместимым.

Обновлённый лаунчер требует optional-max-hold-v1. Старые процессы не перезапускаются. Старый код не поддерживает null: откат сервера допустим только при отсутствии новых конфигураций с null либо с использованием версии, поддерживающей эту форму. Автоматически заменять null на час или удалять данные ради отката нельзя.

Фактически прочитаны cash=99864.63 USD и quantity=0 BTC. Реконструкция только исполнений, без подтверждённых комиссий, даёт cash=98913.196047837870182244 в бюджете сессии и quantity=0.000597584 BTC. Первые два вида расхождения относятся к реконструкции без записей комиссий; старый pending при этом имел более узкую денежную ошибку: текущие 99864.63 ниже его границы на 0.0346579696941312629900 USD. Нельзя смешивать эти два разных расчёта или объявлять разницу в 48.466 USD дополнительной потерей сверх уже прочитанного баланса.

По [официальной документации Alpaca](https://docs.alpaca.markets/us/docs/crypto-fees) записи криптокомиссий запрашиваются как CFEE/FEE и могут появляться после завершения дня. Подменять их оценкой и принудительно закрывать архив нельзя.

## Подтверждённая ошибка кода

В BrokerEngine._sync ветка pending сравнивала позицию и баланс с ожидаемыми диапазонами, затем сразу выбрасывала AlpacaError при расхождении. Проверка начислений `_late_fees` существовала только в соседней ветке без pending. Очистить terminal pending код мог лишь после успешного сравнения. Получался замкнутый цикл: pending не очищается до совпадения баланса, но начисления для объяснения несовпадения не читаются, пока pending существует.

Эта ошибка объясняет отсутствие пути восстановления после повторяющегося расхождения. Она не доказывает, что конкретный старый ответ брокера отличался именно из-за комиссии. Alpaca описывает удержание криптокомиссии из получаемого актива/валюты в [официальной документации](https://docs.alpaca.markets/us/docs/crypto-trading); окончательная проверка конкретной суммы требует записей её счёта.

## Исправление и границы

При расхождении после terminal-заявки без открытых ордеров исполнитель теперь может запустить уже существующее фоновое GET-чтение начислений. Только совпавшие FILL, проверенное владение ордерами, опубликованные комиссии и совпадение полного расчётного баланса/позиции разрешают применить результат. Пока этих доказательств нет, статус остаётся UNRESOLVED, pending сохраняется, POST/DELETE не повторяются. Неизвестное движение средств не списывается произвольно на комиссию.

Новое событие BROKER_RECONCILIATION_MISMATCH и broker.reconciliation сохраняют фактически прочитанные BTC/USD, ожидаемые диапазоны, отдельные результаты проверки количества и денег, терминальность ордера и время. Это диагностические наблюдения; они не заменяют неподтверждённую торговую позицию. После успешного подтверждения статус диагностики становится MATCHED. Произвольные сетевые ответы, ключи и персональные данные счёта не копируются в диагностику.

Для остановленной UNRESOLVED-сессии доступна кнопка «Сверить начисления Alpaca». Она запускает только чтение счёта/позиций/открытых заявок/начислений и сохраняет отчёт. Она не возобновляет исполнителя, не меняет status/cash/quantity/pending незавершённой сессии и не отправляет ордера. Сравнение стратегий по-прежнему требует CLOSED. Фактические остатки из отчёта показаны отдельно; неполные или неоднозначные начисления помечаются причинами.

Capability исправления — terminal-balance-reconciliation-v1. Панель с обоими изменениями запущена на [8788](http://127.0.0.1:8788/); старый сервер не остановлен. Для окончательного расследования пользовательской сессии требуется подключить Alpaca Paper именно на этом сервере. Ключи вводятся только в панели; запускать или восстанавливать торговлю для диагностики не требуется.

Отдельно проверены необъяснённое изменение денег, неблокирующее чтение activities и сохранение неподтверждённого состояния.
