# Продукт и сценарий

## Необязательный срок удержания — 18.10.2026

Пользователь выбрал убрать обязательный часовой выход для новых сессий. Поле «Максимум удержания позиции» необязательно; пустое значение отключает MAX_HOLD. Явно заданный срок остаётся независимым условием защитного выхода. Скользящий стоп, ограничения потери и общий дедлайн сессии сохранены. Настройки существующих сессий не меняются. Совместимость и расследование зависшей сверки — [BALANCE_RECONCILIATION.md](BALANCE_RECONCILIATION.md).

## Скользящий стоп и цель сессии — решение пользователя 15.10.2026

Для новых сессий основное сопровождение позиции — скользящий стоп. Главный ИИ выбирает вход по обработанным данным; обычные выходы по сигналу ИИ/моментума во время сопровождения заменены скользящим стопом. Независимые выходы по риску, максимуму удержания, команде пользователя и дедлайну имеют приоритет. Технический Paper smoke сохраняет проверочный цикл BUY/SELL.

На старте пользователь задаёт расстояние стопа в процентах и, по желанию, желаемый результат к концу сессии в процентах стартового бюджета. Панель показывает эквивалент цели в USD. Это мягкий ориентир для ИИ: недостижение допустимо; цель не разрешает повысить риск/размер/экспозицию, расширить стоп, продлить дедлайн или делать необоснованные сделки ради отыгрыша. Достижение цели не вызывает автоматическую покупку, продажу или завершение. Текущий результат для сравнения с целью включает оценку расходов на закрытие открытой позиции.

Стоп ведётся локальным исполнителем по проверенным котировкам; сервер должен работать. Расстояние 2 % по умолчанию сохранено от прежней настройки начального стопа как техническое значение, не рекомендация. Вход сам по себе не определяется скользящим стопом: прежний исследовательский кандидат и независимый Risk Engine сохранены. Старые сессии остаются со своими правилами.

## Назначение

Персональный комплекс автономной торговли криптовалютой. Пользователь управляет рамками сессии, система — действиями внутри этих рамок. Главный ИИ принимает решения по обработанным данным. Горизонт — несколько часов, возможно день.

Целевой результат сессии: подтверждённое состояние средств, закрытие управляемых позиций насколько позволяет биржа, отсутствие забытых активных ордеров и отчёт о результате после расходов. Доходность — предмет проверки, а не обещание продукта.

Пользователю нет 18: в текущем предлагаемом MVP средства, позиции и исполнения виртуальные, состояние подтверждает собственный симулятор. Публичные котировки берутся только из доступного по условиям источника. Описания биржевого исполнения ниже относятся к отложенной будущей версии; её доступность по возрасту и региону не установлена.

## Пользовательский сценарий

1. Выбрать режим: исследование, paper или отдельно включённый live в будущей версии.
2. Выбрать биржу, бюджет сессии, расчётную валюту, инструменты и профиль риска.
3. Указать время завершения с датой и часовым поясом либо длительность.
4. Получить проверку совместимости настроек и понятные численные лимиты.
5. Запустить сессию. Видеть её состояние, результат, позиции и причину последнего действия/ожидания.
6. При необходимости запретить новые входы или инициировать завершение.
7. Получить итог: сделки, комиссии, расходы LLM/данных, реализованный и нереализованный результат, максимальная просадка и остатки.

Закрытие интерфейса не должно означать прекращение управления позициями. На личном компьютере сон или выключение нарушает доступность; постоянный сервер — отдельный вариант будущего запуска.

## Настройки

| Настройка | Смысл |
| --- | --- |
| Бюджет сессии | Максимум выделенных средств, отдельно от остального аккаунта |
| Расчётная валюта | Единица бюджета и результата; имеет собственный рыночный риск |
| Риск на сделку | Допустимая расчётная потеря до защитного выхода, не размер покупки |
| Лимит потери сессии | Условие запрета входов и начала завершения |
| Лимит просадки | Ограничение падения equity от максимума сессии |
| Общая экспозиция | Допустимый объём одновременно открытого риска |
| Число позиций | Ограничение параллельных позиций и резервов под ордера |
| Разрешённые инструменты | Явный whitelist; ИИ не добавляет символы самостоятельно |
| Дедлайн | Целевое время отсутствия управляемых позиций и активных ордеров |
| Буфер завершения | Время для прекращения входов, отмен и закрытия до дедлайна |
| Максимум удержания | Ограничение отдельной позиции в пределах сессии |
| Лимит расходов | Бюджет LLM и внешних данных; защитные действия от него не зависят |

Профили риска раскрываются в конкретные значения. Числа пока не выбраны; более высокий риск не означает более высокую ожидаемую прибыль.

## Предлагаемый MVP

Один пользователь, источник публичных котировок без обязательного торгового аккаунта, симуляция спота без заимствования, одна проверяемая стратегия, небольшой набор ликвидных пар, paper, запуск и завершение сессии, история решений и расходов. ИИ выбирает из разрешённых кандидатов и может ждать; расчёты выполняются кодом. Виртуальный PnL моделируется, а реальные расходы на данные/LLM учитываются отдельно.

Фьючерсы, плечо, шорты, несколько бирж, арбитраж, высокочастотная торговля, самостоятельное написание стратегий в live и публичный многопользовательский сервис — возможные отдельные направления после MVP. Спот пока не согласован пользователем.

## Критерии продукта

- Перед запуском все обязательные лимиты заданы и непротиворечивы.
- У каждого действия есть снимок данных, объяснение, результат риск-проверки и фактическое исполнение.
- «Ничего не делать» — нормальное состояние при отсутствии допустимого сигнала.
- По дедлайну есть проверяемый статус закрытия; неизвестное состояние не называется успехом.
- После рестарта система узнаёт реальные ордера и остатки до новых входов.
- Результат включает комиссии и операционные расходы; нереализованный PnL показывается отдельно.
- Решение о реальных средствах следует отдельному этапу оценки стратегии и надёжности.
